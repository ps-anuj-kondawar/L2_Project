🔒 Why MCP over In-Process Function Calling?

1. Process Sandboxing & Security:

The hardware evaluation engine runs in a separate OS process. A fatal memory leak or unhandled exception in tool code cannot take down the core FastAPI web server.

2. Dynamic Runtime Discovery:

The client agent queries session.list_tools() at runtime to dynamically inspect parameters, rather than baking hardcoded function signatures into the agent.

3. Universal Interoperability:

Any external MCP client (Claude Desktop, IDE agents, autonomous CLI orchestrators) can connect directly to ChemShield's FastMCP server without rewriting tool wrappers.

Architectural Rationale & Defense

Why Our Approach vs Industry Shortcuts

In safety-critical chemical engineering, conventional AI design patterns fail catastrophically. Here is how ChemShield solves each challenge.

1. Monolithic Prompt vs Multi-Agent ReAct

Industry Shortcut: Single giant prompt asking LLM to do extraction, math, and full 16-section writing.
ChemShield Solution: Decoupled ReAct Supervisor orchestrating isolated specialists with typed Pydantic schemas.
Prevented: CAS number hallucination & missed physics checks

2. Pure Vector RAG vs 5-Tier Retrieval

Industry Shortcut: Ingesting raw PDF regulatory tables into ChromaDB vector search.
ChemShield Solution: Tier 1 Master DB ($O(1)$) priority for top 22 chemicals, falling back to RAG, cache, and web.
Prevented: Table chunk boundaries splitting rows and assigning wrong limits

3. Fail-Open vs Fail-Closed Philosophy

Industry Shortcut: Defaulting to COMPLIANT / SAFE if a chemical is unindexed.
ChemShield Solution: All data models default strictly to REVIEW_REQUIRED. Passing requires positive proof.
Prevented: Mistaking absence of data for regulatory safety

4. Direct Output vs Reflection Gate

Industry Shortcut: Returning raw LLM-authored SDS directly to user.
ChemShield Solution: 9-point automated ReflectionAgent audit + bounded revision retry loop.
Prevented: Missing PPE, invalid UN codes, missing IARC cancer warnings
Evaluation Master Cheat-Sheet

High-Yield Viva Defense Q&A

Comprehensive technical answers for evaluation defense covering regulatory statutes, code locations, and failure-mode prevention.

Q1: Why can't you directly compare liquid % to airborne ppm?

Answer: ppm in OSHA 29 CFR 1910.1000 measures airborne vapor concentration over an 8-hour workday for worker inhalation, whereas % measures liquid mixture composition. They are physically distinct quantities. ChemShield flags general liquid comparisons as REVIEW_REQUIRED for industrial hygiene air monitoring. For Benzene specifically, 29 CFR 1910.1028 defines a separate 0.1% liquid formulation ceiling, which ChemShield checks directly.

Code: src/agents/chemical_agent.py:432-472

Q2: How does ChemShield handle token and operational cost?

Answer: Through five layers: (1) SQLite WAL caching keyed by SHA-256 hash yields ~0.005s repeated runs with 0 tokens; (2) O(1) Master DB bypasses LLM calls for top 22 chemicals; (3) Task-specific prompts avoid context bloat; (4) ChromaDB RAG_TOP_K = 5 bounds chunk retrieval; (5) Fast models (Gemini Flash) handle entity extraction.

Code: src/infrastructure/cache.py

Q3: What was the critical bug fixed regarding GHS signal words?

Answer: When PubChem returned signal_word = None for unclassified compounds, calling .upper() threw an unhandled AttributeError crash. We fixed this in src/utils/ghs_rules.py:239 using (chem_data.get('signal_word') or '').upper(), ensuring fail-safe execution.

Code: src/utils/ghs_rules.py:239

Q4: What are the 9 checks in the Reflection Agent?

Answer: (1) All 16 GHS section headers; (2) CAS validation vs PubChem/Master DB; (3) Section 3 isolation (no exposure limits); (4) Section 8 specific PPE (gloves/respirator/goggles); (5) Section 14 UN shipping code; (6) Section 15 TSCA/SARA/Prop 65 citations; (7) Section 1 CHEMTREC emergency contact; (8) Section 9 physical constants; (9) Section 11 IARC/NTP carcinogen disclosure.
